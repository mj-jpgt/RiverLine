# 2026-08-17 — W3: security hardening

## What I did

- **Research first**, primary sources with URLs + retrieval dates: OWASP Top
  10 (2021 — the 2025 list exists per the project page but its actual
  content wasn't retrievable this session, said so honestly rather than
  guessing), OWASP API Security Top 10 (2023), OWASP Session Management and
  File Upload cheat sheets, the official Next.js CSP guide. Full mapping of
  each item to this codebase's actual status (OK / FIXED-HERE / N/A / OPEN)
  is in `docs/security-review.md`.

- **Route-by-route audit**: read every `app/api/**/route.ts` (16 routes)
  plus the 5 page-adjacent routes under `app/dashboard/export/` and
  `app/letters/[clientId]/` that function as APIs. Every one already had a
  `requireRole` guard and tenant-scoped `withTenant`/RLS access — this
  codebase was already disciplined about this before I touched it. Full
  table in `docs/security-review.md`. Also read (not edited — outside my
  paths) W2's four `a4-estimates` routes; same pattern, but no magic-byte
  sniff or size cap on estimate-document uploads yet — flagged in the
  review doc for W2, not fixed here.

- **`middleware.ts`** (new, root): security headers on every response.
  CSP is nonce + `'strict-dynamic'` (official Next.js pattern, verified
  working on the exact pinned Next 15.5.23 — not assumed), no
  `'unsafe-inline'` in the default policy. `X-Content-Type-Options: nosniff`,
  `X-Frame-Options: SAMEORIGIN` / `frame-ancestors 'self'` (see deviation
  below), `Referrer-Policy: strict-origin-when-cross-origin`,
  `Permissions-Policy: camera=(self), geolocation=(self)`,
  `Strict-Transport-Security` in production only.

- **Found and fixed a real CSP break before it shipped**: the letter print
  route (`app/letters/[clientId]/print/route.ts`) returns a hand-built HTML
  string directly, not React-rendered, so it never gets Next's automatic
  nonce injection. It has a real inline `<style>` block and an inline
  `onclick="window.print()"`. Under the strict default policy this would
  have silently broken letter styling and the print button — I caught this
  by actually reading `src/modules/a1-letters/pure.ts`'s `renderLetterHtml`
  and then confirming via `curl` against a real dev server that the route
  serves a raw string, not React output. Fixed with a narrow,
  well-documented CSP exception scoped to exactly that one route path
  (`middleware.ts`'s `LETTER_PRINT_PATH` branch) — every other route keeps
  the strict policy.

- **`X-Frame-Options`/`frame-ancestors`: `SAMEORIGIN`/`'self'`, not the task
  brief's literal `DENY`** — `app/letters/[clientId]/page.tsx` iframes its
  own same-origin `/print` route for the letter preview; `DENY` would break
  it. Documented deviation.

- **`src/shared/security/rate-limit.ts`** (new): boring in-memory
  sliding-window limiter, `globalThis`-keyed (same trick
  `src/core/auth/dev-link-store.ts` already uses, for the same dev-mode
  module-splitting reason). Wired into `app/api/auth/request-link` (5/15min
  per email, 20/15min per IP), `app/api/auth/verify` (30/15min per IP), and
  `app/api/capture/sync` (30/min per acting user) — all 429 with
  `Retry-After`. Numbers and rationale documented per-route in the review
  doc and inline in each route, not invented as "industry standard."

- **`src/shared/security/upload-validation.ts`** (new): magic-byte sniff
  (jpeg/png/webp) + an 8MB-per-photo / ~48MB-per-request size cap, wired
  into `app/api/capture/sync/route.ts`'s existing photo-verification loop
  (smallest possible diff — the sha256 re-verification loop already existed;
  I added two checks inside it plus one `Content-Length` check at the top
  of the handler). Confirmed `storage_key` is server-generated everywhere
  it's written (grepped every write site) — path traversal via a
  user-supplied id is structurally impossible, not just avoided by
  convention.

- **Tests** (`test/unit/security/`): `rate-limit.test.ts` (limiter logic),
  `upload-validation.test.ts` (magic-byte sniff against a real fixture JPEG
  and several spoofed payloads), `dev-magic-link-gate.test.ts` (imports the
  route directly — it's one of exactly two routes with no
  `cookies()`/`next-headers` call, so unlike every guarded route it's safe
  to import in a unit test), `photo-idor.test.ts` (real Postgres,
  `riverline_test`, two real jurisdictions, exercises the exact query
  `app/api/photos/[id]/route.ts` runs — same pattern T-C1's `rls.test.ts`
  established). `test/e2e/security-headers.spec.ts` asserts the header set
  on `/` and on an unauthenticated API 401, confirms no `'unsafe-inline'` in
  the default CSP, and confirms a fresh nonce every request.

## What I had to debug / verify for real, not assume

1. **Nonce auto-injection actually works on this exact pin.** Ran a real
   `next build` + `next start` (temporarily flipping
   `typescript.ignoreBuildErrors` in `next.config.ts` to get past unrelated,
   in-flight TS errors in W2's concurrently-changing `a4-estimates` module —
   reverted immediately after, confirmed zero net diff via `git diff` before
   moving on). Confirmed via `curl` that every Next-managed `<script>` tag
   in the served HTML carries the same nonce as the response header, with
   zero `app/layout.tsx` changes. Then launched a real headless Chromium
   (Playwright) against the production server, navigated five pages,
   confirmed zero console errors / zero CSP violations, and confirmed
   `navigator.serviceWorker.getRegistrations()` showed the Serwist SW
   registered and active — the CSP genuinely does not break the SW
   (docs/adr/0002's hard requirement).
2. **The letter print route break**, described above — this is exactly
   the kind of thing "test, don't guess" exists to catch, and a curl-only
   pass on `/`, `/login`, `/home` would have missed it entirely since it's
   route-specific raw-string HTML.
3. **`pnpm audit --prod`**: 5 findings, all one chain
   (`next@15.5.23 > postcss@8.4.31`, Next's own bundled internal PostCSS —
   not this project's pinned devDependency `postcss@8.5.26`). All
   build-time-only source-map/XSS issues in a tool that never runs in the
   request path. Documented as OPEN — not fixable without an ADR-worthy
   Next.js version bump, outside this task's scope.
4. **Secret scan**: `git grep` across the whole tracked tree for AWS
   keys/API-key patterns/PEM headers/hardcoded passwords/populated
   `SUPABASE_SERVICE_ROLE_KEY=` — zero matches. `.env.local`/`uploads/`/
   `backups/` all correctly gitignored.

## What is open / deviations

- **`app/api/estimates/**` (W2's module) has no magic-byte sniff or size
  cap on uploaded estimate-document pages** — same gap `/api/capture/sync`
  had before this task, not fixed here (outside my assigned paths). Flagged
  in `docs/security-review.md` for W2's attention.
- **`pnpm audit --prod`**: the transitive PostCSS chain above — documented,
  not fixed (requires a Next.js major bump / ADR).
- **A09 (logging/monitoring)**: no error-monitoring service (build spec
  §11.2 names Sentry) exists anywhere in this codebase yet. Not part of my
  assigned paths; noted for whoever owns it.
- **HSTS / rate-limiter `X-Forwarded-For` trust**: both depend on the
  production reverse proxy actually setting/forwarding the right headers.
  W4 owns deploy (`docs/deploy/`) — coordination note left in
  `docs/security-review.md`, not implemented here per the task's own
  "coordinate via docs only" instruction.
- **`X-Frame-Options`/`frame-ancestors` `SAMEORIGIN`/`'self'` instead of
  `DENY`/`'none'`**, and **the letters-print-route CSP exception** — both
  documented deviations from a literal reading of the task brief, both with
  a concrete, verified reason (an existing same-origin iframe feature would
  have broken).
- **Rate-limit logic lives in route handlers, not `middleware.ts`** — see
  "Deviations" section of `docs/security-review.md` for the Edge-vs-Node
  runtime reasoning.
- **Full `pnpm verify` was not run as one command** — the shared tree's
  concurrently-changing `a4-estimates` TS errors would fail its typecheck
  step for reasons outside this task's scope; every gate this task could
  actually affect was instead run individually. See
  `docs/security-review.md` "Acceptance" for the itemized results.
- **`pnpm test:determination`** (the only e2e path that exercises the
  letters print route with a real adopted determination) was launched to
  get a full end-to-end proof of the CSP-exception fix, but its own recipe
  (seed → cost-table seed → dedicated dev server → ~2-3min Playwright run)
  didn't finish inside this session's time budget alongside everything
  else. Not treated as blocking: the fix was independently confirmed by
  direct `curl` evidence instead (see `docs/security-review.md`
  "Acceptance" for exactly what that showed) that the CSP branch in
  `middleware.ts` correctly discriminates the print route from every other
  route, which is the actual thing being proven.
