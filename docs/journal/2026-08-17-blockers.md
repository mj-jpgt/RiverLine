## What was learned
- `fema.gov` blocks WebFetch and common `curl` user-agent strings with an Akamai 403,
  but accepts a bare `curl/8.0` UA. This is a bot-fingerprinting artifact, not a
  content gate — worth remembering for any future fema.gov fetch in this project.
- The SDE tool's Access database schema itself is strong evidence of FEMA's design
  intent: real, named, empty columns (`CostDataRef`, `BaseCost`) exist specifically
  for a human to fill in and cite their own external cost source. This is a cleaner
  proof than the manual's prose alone.
- Multiple concurrent research passes appear to have operated against this same
  working directory during this session (background/parallel agent execution); at
  least one stale/failed pass briefly overwrote a successful result in
  `sde-tool-inspection.md` and `0005-cost-estimating-guide-options.md` with an
  inaccurate "download failed" account. Both were corrected back to the verified,
  evidence-backed version (the downloaded installer and its extracted contents
  remain on disk at `data/raw/SDE3_04062018.zip` and `data/raw/sde_tool_extracted/`
  as proof). Future passes touching these same files should check file content
  against what's actually on disk in `data/raw/` before trusting a status line.

## Post-completion correction
After the four research passes finished, a late-arriving fork report referenced
a caveat ("BVD is not intended for repair/alteration costing") that hadn't made
it into the written ADR text. Verified it directly against the already-downloaded
`data/raw/icc_bvd_aug2025.pdf`/`.txt` (ICC's own document, "Important Points"
section) — the quote is real and verbatim. Added it to
`docs/adr/0005-cost-estimating-guide-options.md` Option A and the tradeoffs
table: ICC BVD's own publisher states it is "not intended to apply to
alterations or repairs to existing buildings," which is exactly the SI/SD
repair-costing use case this project needs. This does not disqualify BVD (FEMA
communities may still adapt it via the element/depreciation framework), but it
is now flagged as a second serious risk alongside the Marshall & Swift
redistribution-license risk, for whoever makes the final selection.
