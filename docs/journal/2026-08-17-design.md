## What failed contrast, and what I substituted

Three of USWDS's literal named "state" theme-role defaults failed the
4.5:1 AA floor against `--color-surface` (`#f0f0f0`). In every case I
picked a **darker real USWDS grade from the same color family** rather
than inventing a value, and documented the substitution inline in
`tokens.css`:

- **Green (NOT_SD):** `theme-color-success` (`green-cool-40v`, `#00a91c`)
  = 2.75:1, and `success-dark` (`green-cool-50v`, `#008817`) = 4.06:1 —
  both fail. Substituted `success-darker` (`green-cool-60v`, `#216e1f`,
  still a named USWDS theme role) = **5.56:1, passes.**
- **Gold (BORDERLINE):** every named "warning" role fails —
  `warning-dark` (`gold-30v`) = 1.97:1, `warning-darker` (`gold-50v`,
  `#936f38`) = 4.03:1, short of 4.5. Substituted `gold-60v` — a real USWDS
  system color token in the same family/vivid ramp, one grade darker than
  the named role — = **5.63:1, passes.**
- **Red (SD):** `theme-color-error` default (`red-warm-50v`, `#d54309`) =
  3.97:1, fails. Substituted USWDS's `theme-color-emergency` role
  (`red-warm-60v`, `#9c3d10`, also a named theme token, semantically apt
  for "substantial damage") = **5.97:1, passes.**

All other tokens (text, muted, border, action fills, draft status,
danger) were chosen from named USWDS theme roles that passed on the first
try.

## shadcn / React 19 / Tailwind verdict

Compatible, low friction. shadcn/ui declares full support for React 19 +
Tailwind v4 in its `latest` release. The one documented friction point —
npm peer-dependency conflicts on packages not yet declaring React 19
support (recharts named explicitly) — doesn't apply to us: this repo uses
pnpm, and shadcn's docs state pnpm/yarn/bun resolve with silent warnings,
no `--force`/`--legacy-peer-deps` needed. Tailwind v3 remains supported
non-breakingly; v4's `@theme` mechanism maps more directly onto our
semantic tokens, so `components.md` assumes v4, but the mapping table
holds either way — only the CSS syntax changes. Full mapping table
(shadcn CSS variable → our token) is in `components.md` §2.
