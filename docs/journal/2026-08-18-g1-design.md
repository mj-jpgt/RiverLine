### 1. Tokens (`docs/design/tokens.css`)

Refined the palette to the v2 amendment's "white, blue, gray... cool
near-white surfaces, a strong blue accent family" directive, re-pulling four
color tokens from real USWDS grades at the same `v3.13.0` tag already cited
in the file (never invented, every value has a source file + retrieval date
inline):

- `--color-surface`: `#f0f0f0` (gray-5, plain/warm family) → `#f5f6f7`
  (gray-**cool**-3) — a genuinely cool near-white.
- `--color-text`: `#1b1b1b` (gray-90) → `#1c1d1f` (gray-**cool**-90) — matches
  the new cool surface instead of mixing warm/cool grays.
- `--color-action-hover`: `#1a4480` (blue-**warm**-70v) → `#0b4778`
  (plain **blue**-70v) — same family as `--color-action` (blue-60v), not a
  mixed blue/blue-warm ramp.
- `--color-action-pressed`: `#162e51` (blue-**warm**-80v) → `#112f4e`
  (plain **blue**-80v), same reasoning.

Fonts: replaced the USWDS-default-face tokens with `next/font` variable
references (`--font-public-sans`, `--font-ibm-plex-mono`, generated by
`app/layout.tsx`) — Public Sans is itself USWDS's own current typeface, so
this keeps the institutional register while satisfying the amendment's
explicit pairing.

Added two new tokens for the new entrance-motion category:
`--motion-entrance-duration: 260ms`, `--motion-entrance-stagger: 60ms` — a
separate tier from the existing `--motion-fast`/`--motion-base` (100ms/
140ms), which are **unchanged** and still govern every functional
state-change transition everywhere, including inside the three v2 surfaces.

### 5. `prefers-reduced-motion` + new e2e assertions

`src/shared/ui/Entrance.tsx`'s `useEntranceInitial()` returns `false` under
reduced motion, which is `motion/react`'s documented "no mount animation at
all" state — proven via `Element.getAnimations()` in the new e2e tests, not
just a duration read. `CountUp` renders the real final formatted value on
first paint always (SSR included) and only plays the from-zero tween inside
a post-mount effect gated on a confirmed `reduceMotion === false` — a
stricter guarantee than the spec technically requires, because a transient
wrong number on a screen an official might read aloud is not an acceptable
trade for polish (AGENTS.md "no hardcoded/fake data", "output has legal
consequences").

`test/e2e/motion.spec.ts` got a new `"Design v2 — fonts, entrance motion, no
emojis"` describe block (6 tests, all passing — see PASS/FAIL table below):
Public Sans / IBM Plex Mono computed-font assertions, a real staggered
`motion` animation proven via `Element.getAnimations()` under normal
settings, the same proven **absent** under reduced motion, and a
`\p{Extended_Pictographic}` regex sweep of the rendered landing and home
HTML (assessor + official views) proving zero emoji characters anywhere.

## Environment notes (shared working tree)

This session ran on the shared, non-isolated working tree with several
other agents' dev servers active concurrently (ports 3001/3055/4950 seen in
`tasklist` alongside my assigned 4700). Hit, and worked around, three
distinct shared-environment failures during verification, none caused by
this task's diff:

1. `.next` `EINVAL`/`ENOENT` mid-compile (the documented "another agent's
   `.next` collision" — `.next/` is per-repo-checkout, not per-port, so
   concurrent `next dev` processes on different ports still share and can
   corrupt the same build cache). Fixed each time by deleting `.next` and
   restarting, per the standard recipe.
2. `node_modules/.bin/next` briefly missing mid-session — almost certainly
   a concurrent `pnpm install`/`pnpm add` from another agent rewriting the
   shared `node_modules/.bin` symlinks. Fixed with `pnpm install` (lockfile
   already up to date, restored the bin symlink, no dependency changes).
3. Intermittent login-flow timeouts (`pressSequentially`/`getByRole("status")`
   not resolving) in **other agents' modules** (registry, capture,
   security-headers, multi-device-sync, a2/a4/g4 specs) during a full-root
   sweep with concurrent workers — never in the same files when re-run in
   isolation or at lower concurrency. Consistent with the machine being
   genuinely overloaded (multiple agents' dev servers + Playwright workers
   + OneDrive sync all contending for the same disk), not a functional
   regression — none of those files are in this task's diff.
4. A `pnpm build` attempt (tried as a more stable alternative to repeated
   dev-mode cold compiles) failed at "Collecting page data" with
   `PageNotFoundError` for routes that definitely exist
   (`/api/calculation/compute`, `/api/capture/sync`) — the same class of
   shared-`.next`-directory corruption as (1), this time hitting a
   production build instead of dev mode. Abandoned that approach and went
   back to dev mode with an immediate clean `.next` + single dev process,
   which is what actually produced the screenshots below.
5. `test/e2e/users.spec.ts` (present in the tree, a concurrent agent's
   work) throws at module load if run outside its own dedicated runner —
   excluded it explicitly by naming files rather than editing
   `playwright.config.ts`'s `testIgnore` (outside my assigned paths).
